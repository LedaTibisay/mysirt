Was MySirt ist

Kernbeschreibung

MySirt ist eine Model Execution Engine, die Domänenwissen ausführbar macht, durch ein deklaratives Modell und eine model-driven Ausführungsarchitektur. Strukturierte Modelle werden von der Execution Engine interpretiert und in ausführbare Informationssysteme transformiert.

Low-Code-Eigenschaften können aus dieser Architektur entstehen, sind aber nicht ihr organisierendes Prinzip. Das Modell ist das primäre Artefakt, und das ausführbare System wird daraus abgeleitet. Das Modell bleibt die Single Source of Truth über den gesamten Systemlebenszyklus hinweg.

Model-Driven-Prinzip

MySirt arbeitet auf Modellebene. Domänenmodelle beschreiben Struktur, Verhalten und Verantwortlichkeiten. Die Engine interpretiert diese Modelle und erzeugt ausführbare Systeme. Das Modell ist das primäre Artefakt.

Was MySirt erzeugt

  • Datenbankschema
  • Backend-Services
  • Weboberfläche
  • Formulare und Datenansichten
  • Workflows
  • Durchsetzung von Geschäftsregeln
  • Rollenbasierte Sicherheit
  • Benachrichtigungen und Berechnungen

Das generierte System kann datenorientierte Anwendungen oder verantwortungsgetriebene operative Workflows darstellen.

Für wen es gedacht ist

  • Organisationen, die komplexe, regelbasierte Geschäftsprozesse digitalisieren
  • Teams, die wiederkehrende Prozessvarianten über mehrere Kunden hinweg verwalten
  • Anbieter, deren Domänenwissen zu einem ausführbaren Informationssystem werden muss

Was MySirt nicht ist

  • Ein visueller Anwendungs-Builder
  • Ein Werkzeug für Business-Anwender
  • Eine SaaS-Plattform
  • Ein Generator für Code-Scaffolding

Warum es anders ist

MySirt gehört zur architektonischen Kategorie der Model Execution Engine. Ihr Zweck ist es, ein deklaratives Modell über die Zeit konsistent auszuführen. Domänenwissen ausführbar zu machen ist das architektonische Ziel. Die Reduktion von manuell geschriebenem Code ist eine natürliche Folge dieses Ansatzes.

Eine andere architektonische Perspektive

Traditionelles Low-Code MySirt Model Execution Engine
Reduziert primär manuell geschriebenen Anwendungscode. Führt ein deklaratives Modell als primäres Systemartefakt aus.
Die ausgelieferte Anwendung ist häufig das zentrale Artefakt. Das Modell bleibt die Single Source of Truth über den gesamten Systemlebenszyklus hinweg.
Das Modell unterstützt üblicherweise Konstruktion oder Konfiguration. Das Modell definiert Struktur, Verhalten und organisatorische Regeln.
Die Architektur ist häufig um den Zusammenbau der Anwendung organisiert. Die Architektur ist um Modellinterpretation und Runtime-Ableitung organisiert.
Änderungen werden über Plattformkonfiguration oder visuelle Komposition eingeführt. Änderungen werden durch Anpassung des ausführbaren Modells und Regeneration kohärenter Runtime-Strukturen eingeführt.

In MySirt beschreiben Benutzer, was das System ist und wie es sich verhält. Die Execution Engine bestimmt, wie diese Spezifikation zu einem ausführbaren Informationssystem wird.

Engine-Logik

MySirt verhält sich wie ein Compiler für ausführbare Informationssysteme. Die Execution Engine arbeitet als Systemgenerierungs-Engine, in der die ausführbare Anwendung direkt aus dem Modell abgeleitet wird. Änderungen am Modell restrukturieren das Verhalten kohärent.

Bezug zu KI

KI kann Benutzer beim Authoring deklarativer Modelle unterstützen, etwa indem sie hilft, eine Domäne zu analysieren und mögliche Strukturen, Beziehungen, Verhaltensweisen und Geschäftsregeln zu entwerfen. Das Modell bleibt die Single Source of Truth. MySirt führt dieses Modell über die Execution Engine aus und bewahrt deterministische Ableitung, Konsistenz, Reproduzierbarkeit und architektonische Kohärenz.

Abschließende Aussage

MySirt ist kein schnellerer Weg, Software zu entwickeln. Es ist eine Model Execution Engine, die Domänenwissen über eine Single Source of Truth ausführbar macht.
