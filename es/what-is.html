Qué es MySirt

Definición central

MySirt es un Model Execution Engine que hace ejecutable el conocimiento de dominio mediante un modelo declarativo y una arquitectura de ejecución model-driven. Los modelos estructurados son interpretados por el Execution Engine y transformados en sistemas de información ejecutables.

Las características low-code pueden surgir de esta arquitectura, pero no son su principio organizador. El modelo es el artefacto principal y el sistema ejecutable se deriva de él. El modelo permanece como Single Source of Truth durante todo el ciclo de vida del sistema.

Principio Model-Driven

MySirt opera a nivel de modelo. Los modelos de dominio describen estructura, comportamiento y responsabilidades. El motor interpreta estos modelos y produce sistemas ejecutables. El modelo es el artefacto principal.

Qué genera MySirt

  • Esquema de base de datos
  • Servicios backend
  • Interfaz web
  • Formularios y vistas de datos
  • Workflows
  • Aplicación de reglas de negocio
  • Seguridad basada en roles
  • Notificaciones y cálculos

El sistema generado puede representar aplicaciones centradas en datos o workflows operativos guiados por responsabilidades.

Para quién es

  • Organizaciones que digitalizan procesos de negocio complejos basados en reglas
  • Equipos que gestionan variantes de procesos recurrentes entre múltiples clientes
  • Proveedores cuyo conocimiento de dominio debe convertirse en un sistema de información ejecutable

Qué no es MySirt

  • Un constructor visual de aplicaciones
  • Una herramienta para usuarios de negocio
  • Una plataforma SaaS
  • Un generador de scaffolding de código

Por qué es diferente

MySirt pertenece a la categoría arquitectónica de los Model Execution Engine. Su propósito es ejecutar un modelo declarativo de forma coherente a lo largo del tiempo. Hacer ejecutable el conocimiento de dominio es el objetivo arquitectónico. La reducción del código escrito manualmente es una consecuencia natural de este enfoque.

Una perspectiva arquitectónica diferente

Low-Code tradicional MySirt Model Execution Engine
Reduce principalmente el código de aplicación escrito manualmente. Ejecuta un modelo declarativo como artefacto principal del sistema.
La aplicación entregada suele ser el artefacto principal. El modelo permanece como Single Source of Truth durante todo el ciclo de vida del sistema.
El modelo suele apoyar la construcción o la configuración. El modelo define estructura, comportamiento y reglas organizativas.
La arquitectura suele organizarse alrededor del ensamblaje de la aplicación. La arquitectura se organiza alrededor de la interpretación del modelo y la derivación Runtime.
Los cambios se introducen mediante configuración de plataforma o composición visual. Los cambios se introducen modificando el modelo ejecutable y regenerando estructuras Runtime coherentes.

En MySirt, los usuarios describen qué es el sistema y cómo se comporta. El Execution Engine determina cómo esa especificación se convierte en un sistema de información ejecutable.

Lógica del motor

MySirt se comporta como un compilador para sistemas de información ejecutables. La Execution Engine opera como un motor de generación de sistemas en el que la aplicación ejecutable se deriva directamente del modelo. Modificar el modelo reestructura el comportamiento de forma coherente.

Relación con la IA

La IA puede asistir a los usuarios durante el authoring de modelos declarativos, por ejemplo ayudando a analizar un dominio y a preparar borradores de estructuras, relaciones, comportamientos y reglas de negocio. El modelo permanece como Single Source of Truth. MySirt ejecuta ese modelo mediante el Execution Engine, preservando derivación determinista, consistencia, reproducibilidad y coherencia arquitectónica.

Conclusión

MySirt no es una forma más rápida de desarrollar software. Es un Model Execution Engine que hace ejecutable el conocimiento de dominio mediante una Single Source of Truth.
