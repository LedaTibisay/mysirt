Überblick über das Ausführungsmodell

Der Systemlebenszyklus wird durch einen deterministischen Ausführungszyklus gesteuert:

  1. Domänenmodell definieren
  2. Execution Engine ausführen
  3. Ausführbares System erhalten
  4. Modell ändern → neu generieren

Was das Ausführungsmodell definiert

  • Datenstrukturen (Entitäten, Beziehungen, Identifikatoren)
  • Operatives Verhalten (Trigger, Jobs, Bedingungen)
  • Organisatorische Verantwortlichkeiten (Rollen, Zugriffsregeln)
  • Workflow-Beschränkungen und Entscheidungsregeln
  • Benutzerinteraktionsstrukturen (Listen, Formulare, Prompts)

Das Modell definiert nicht nur Datenstrukturen, sondern auch das Systemverhalten.

Model-Driven Execution

Das Systemverhalten wird nicht implementiert — es wird aus dem Modell abgeleitet.

Das Modell definiert Struktur, operative Logik und Verantwortlichkeiten. Die Execution Engine interpretiert diese Definition und setzt sie zur Laufzeit durch.

Das Verhalten der Anwendung wird somit durch die Modellstruktur bestimmt und nicht durch schrittweise implementierte Funktionen.

Das laufende System spiegelt seine aktuelle Definition wider und nicht die Ansammlung früherer Codeänderungen.

Strukturelle Kohärenz wird durch model-driven Ausführung und Regeneration gewährleistet.

Was MySirt unterscheidet

Die Domäne wird beschrieben, nicht programmiert. Die DSL wird zur Single Source of Truth, während die Model Execution Engine automatisch ein vollständiges, konsistentes und regenerierbares Informationssystem ableitet.

Positionierung

MySirt ist weder ein Entwicklungstool noch eine Low-Code-Plattform. Es ist eine Model Execution Engine, die Domänenwissen ausführbar macht und das System kontinuierlich mit seiner formalen Definition ausgerichtet hält.
