Execution Model Overview

The system lifecycle is governed by a deterministic execution cycle:

  1. Define domain model
  2. Run Execution Engine
  3. Get executable system
  4. Modify model → regenerate

What the Execution Model Defines

  • Data structures (entities, relations, identifiers)
  • Operational behavior (triggers, jobs, conditions)
  • Organizational responsibilities (roles, access rules)
  • Workflow constraints and decision rules
  • User interaction structures (lists, forms, prompts)

The model defines not only data structures but system behavior.

Model-Driven Execution

System behavior is not implemented — it is derived from the model.

The model defines structure, operational logic and responsibilities. The Execution Engine interprets this definition and enforces it at runtime.

Application behavior is therefore constrained by the model structure rather than shaped by incremental feature implementation.

The running system reflects its current definition, not the accumulation of past code changes.

Structural coherence is preserved through model-driven execution and regeneration.

What Makes MySirt Different

The domain is described, not programmed. The DSL becomes the Single Source of Truth, while the Model Execution Engine automatically derives a complete, consistent, and regenerable information system.
