Visión general del modelo de ejecución

El ciclo de vida del sistema está gobernado por un ciclo de ejecución determinista:

  1. Definir el modelo de dominio
  2. Ejecutar el Execution Engine
  3. Obtener el sistema ejecutable
  4. Modificar el modelo → regenerar

Qué define el modelo de ejecución

  • Estructuras de datos (entidades, relaciones, identificadores)
  • Comportamiento operativo (triggers, jobs, condiciones)
  • Responsabilidades organizativas (roles, reglas de acceso)
  • Restricciones de workflow y reglas de decisión
  • Estructuras de interacción con el usuario (listas, formularios, prompts)

El modelo define no solo las estructuras de datos, sino también el comportamiento del sistema.

Ejecución model-driven

El comportamiento del sistema no se implementa — se deriva del modelo.

El modelo define la estructura, la lógica operativa y las responsabilidades. El Execution Engine interpreta esta definición y la aplica en tiempo de ejecución.

El comportamiento de la aplicación está, por tanto, condicionado por la estructura del modelo y no por implementaciones incrementales de funcionalidades.

El sistema en ejecución refleja su definición actual, no la acumulación de cambios de código a lo largo del tiempo.

La coherencia estructural se preserva mediante ejecución y regeneración model-driven.

Qué hace diferente a MySirt

El dominio se describe, no se programa. La DSL se convierte en la Single Source of Truth, mientras que el Model Execution Engine deriva automáticamente un sistema de información completo, coherente y regenerable.

Posicionamiento

MySirt no es una herramienta de desarrollo ni una plataforma low-code. Es un Model Execution Engine que hace ejecutable el conocimiento de dominio mientras mantiene el sistema continuamente alineado con su definición formal.
