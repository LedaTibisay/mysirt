Modelo de Ejecución

Principio de ejecución

En MySirt el sistema no se implementa — se deriva.

Las aplicaciones no se escriben directamente en código. Se derivan a partir de modelos estructurados expresados a través del meta-modelo de ejecución.

Una definición formal describe datos, comportamiento y responsabilidades. El motor de ejecución interpreta esta definición y produce el sistema de información que la hace efectiva.

La aplicación en ejecución permanece como una consecuencia directa del modelo, no como un artefacto independiente que evoluciona por separado.

Fundamentos de la DSL ejecutable

Definición base

La DSL de MySirt es un lenguaje declarativo utilizado para definir sistemas de información operativos completos. Describe la estructura, el comportamiento y las reglas organizativas dentro de una única definición formal.

Dimensiones del sistema

Un modelo MySirt define tres dimensiones fundamentales de un sistema:

  • Estructura — entidades, campos y relaciones
  • Comportamiento — triggers, jobs y reglas operativas
  • Organización — roles y políticas de acceso

En conjunto, estos elementos constituyen la especificación ejecutable de la aplicación.

Modelo en lugar de código

La DSL describe qué debe hacer el sistema, no cómo se implementa. El motor de ejecución interpreta el modelo y genera la aplicación operativa.

Sistemas completos en una única definición

Un sistema de negocio completo puede definirse dentro de un único archivo DSL. La definición incluye estructuras de datos, workflows, reglas de seguridad y estructuras de interacción necesarias para la aplicación.

Comportamiento operativo en el modelo

Los triggers y jobs permiten modelar directamente los workflows operativos dentro de la definición del sistema.

La lógica de negocio se expresa de forma declarativa sin implementación procedimental.

Principio del modelo de ejecución

La DSL actúa como el modelo ejecutable del sistema. El motor deriva la aplicación en tiempo de ejecución y aplica las reglas definidas en la especificación.

Meta-modelo de ejecución

Qué, no cómo.

MySirt se basa en un meta-modelo que describe las estructuras fundamentales de los sistemas de información operativos. Las aplicaciones no se implementan funcionalidad por funcionalidad; se derivan a partir de modelos construidos sobre esta estructura de ejecución.

La claridad emerge a través de la ejecución.

  • Entidades y relaciones
  • Reglas de negocio
  • Roles y permisos
  • Lógica de workflow

  • Las estructuras son validadas
  • Las dependencias se resuelven

  • Entorno ejecutable derivado del modelo
  • Comportamiento gobernado por definiciones
  • Responsabilidades integradas en el sistema
4

Iterar estructuralmente

  • Modificar el modelo
  • Regenerar el sistema
  • Mantener coherencia estructural

Operación continua del modelo

El sistema generado no es un artefacto final. El entorno operativo permanece derivado del modelo durante todo su ciclo de vida.

La evolución del sistema se produce modificando las definiciones, no la implementación.

Regeneración estructural

Los cambios a nivel de modelo se propagan de forma coherente al sistema. El modelo permanece como la única fuente de verdad.

El modelo como artefacto principal

El modelo no es documentación. Es una especificación ejecutable. El sistema es la ejecución del modelo.

Extensión controlada

El comportamiento personalizado puede integrarse en puntos de extensión definidos. La lógica manual opera dentro de la estructura definida por el modelo, sin reemplazarla.

Impacto en ingeniería

El esfuerzo de desarrollo se desplaza de escribir código a definir comportamiento. La complejidad pasa del volumen de implementación a la claridad del modelo.

Por qué esto cambia el desarrollo

El desarrollo tradicional es code-first y la estructura emerge con el tiempo. MySirt es model-first: la estructura se define desde el inicio y la lógica se formaliza. Esto transforma el desarrollo de codificación incremental en ejecución estructural.
