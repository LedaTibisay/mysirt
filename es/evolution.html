Evolución del Engine

MySirt evoluciona preservando su core de ejecución centrado en el modelo. Los principios fundamentales permanecen estables: definición formal, interpretación determinista, derivación del sistema y regeneración estructural.

La evolución se produce extendiendo las capacidades expresivas de la DSL, del Model Execution Engine, de los mecanismos de generación y de los componentes runtime compartidos, preservando la coherencia arquitectónica y la ejecución determinista.

Principio fundamental

  • Describir un sistema de forma formal
  • Interpretar el modelo de manera determinista
  • Derivar estructuras ejecutables
  • Mantener coherencia estructural en el tiempo

Este principio permanece inalterado desde la concepción original del engine.

Estado arquitectónico

  • DSL declarativa como especificación formal del sistema
  • Intérprete del modelo con validación estructural
  • Capa de derivación determinista del sistema
  • Ejecución de reglas integrada en la generación estructural
  • Capacidad de regeneración coherente

Evolución a través de proyectos reales

El MySirt Execution Engine evoluciona a través de requisitos que emergen de sistemas generados reales.

Un proyecto puede introducir inicialmente una capacidad necesaria para un contexto operativo específico. Cuando esa capacidad demuestra ser reutilizable en distintos dominios, puede generalizarse e incorporarse a la plataforma mediante extensiones coordinadas de la DSL, del Model Execution Engine, de los templates de generación o de los componentes runtime compartidos.

A partir de ese momento, la capacidad deja de ser una implementación específica de proyecto. Pasa a formar parte del vocabulario estándar de modelado y de las capacidades de ejecución disponibles para sistemas futuros.

Del requisito específico a la capacidad de plataforma

  • Surge un requisito concreto en un sistema generado
  • El requisito se implementa y se valida en su contexto operativo
  • Se evalúa su aplicabilidad general
  • La capacidad se formaliza dentro de la arquitectura MySirt
  • La DSL y el Execution Engine se extienden cuando es necesario
  • La capacidad se vuelve reutilizable en futuros sistemas generados

MySirt evoluciona aumentando lo que puede expresarse y ejecutarse a través del modelo, no acumulando implementaciones custom aisladas.

Ejemplos de evolución del Engine

  • Templates de documentos imprimibles
  • Mejoras de seguridad derivadas de penetration testing
  • Generación y ejecución multilingüe de sistemas
  • Mecanismos de notificación y comunicación
  • Mejoras de infraestructura runtime
  • Patrones reutilizables de workflow y ejecución

Estos ejemplos representan capacidades que pueden pasar de una necesidad de proyecto individual a una parte reutilizable del ecosistema MySirt.

Authoring del modelo asistido por IA

La Inteligencia Artificial complementa MySirt ayudando a los usuarios a comprender y describir el conocimiento de dominio antes de que se formalice en el modelo declarativo. Puede ayudar a identificar entidades y relaciones candidatas, sugerir comportamientos y preparar borradores de reglas de negocio para su posterior validación y formalización.

Rol en el authoring

  • Comprensión del dominio y análisis estructural
  • Borrador de entidades, relaciones, comportamientos y reglas
  • Asistencia en el refinamiento de las definiciones del modelo
  • Apoyo para producir especificaciones ejecutables más claras

Límite arquitectónico

  • La IA asiste la modelización; no ejecuta el sistema
  • El modelo declarativo validado permanece como Single Source of Truth
  • La IA puede proponer contenido del modelo; solo el modelo declarativo validado se interpreta y ejecuta
  • El Model Execution Engine sigue siendo responsable de la interpretación determinista
  • Las estructuras Runtime se derivan del modelo, no de inferencia de IA

La IA puede mejorar la productividad de la modelización, pero no sustituye la arquitectura de ejecución. Determinismo, consistencia, reproducibilidad y coherencia arquitectónica siguen siendo responsabilidades del MySirt Execution Engine.

Flujo conceptual de integración

Domain Knowledge → AI-Assisted Modeling → Declarative DSL → Model Execution Engine → Executable Information System

MySirt executes formal models, not probabilistic outputs.

Posición arquitectónica

  • La IA es una capa asistiva para el análisis del dominio y el authoring del modelo
  • El modelo declarativo validado permanece como Single Source of Truth
  • El Model Execution Engine permanece estable, independiente y determinista
  • Ninguna responsabilidad de ejecución se transfiere a la IA
  • Las nuevas capacidades reutilizables pasan a formar parte de la plataforma mediante una evolución arquitectónica controlada
